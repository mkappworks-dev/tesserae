# Edits and emitters survive in coarse LOD levels

Status: needs-info
Blocked by: a save step (no spec or ticket for it exists yet)

Step 6 derives every coarse Chunk from the generator plus the level-0 Chunks the
Server happens to hold that an Edit changed
([ADR-0011](../../../docs/adr/0011-coarse-levels-are-derived.md)). Once level 0
is durable that is the wrong source. This ticket is the change that makes the
coarse levels read level 0 instead, and keeps a placed lantern visible at
distance.

## What it is blocked on

Nothing here can be built or even sized until the save step settles four things.
Each is a question for that step, and this ticket's design assumes the answer
given.

1. **An evicted level-0 Chunk comes back with its Edits.** Today eviction throws
   an edited Chunk away and the generator remakes it without the Edit. The
   assumption: the Server reloads it from the save, and a Chunk the save has
   never seen is the generator's.
2. **The save can say which level-0 coordinates it holds, without reading
   them.** A sparse set of coordinates, held in memory, is enough. If the save
   instead stores every generated Chunk, nothing distinguishes an edited Chunk
   from an untouched one and the cheap path below is lost.
3. **A Chunk can be read from the save by a Job.** ADR-0007 hands a Job `Arc`s
   and takes an owned value back, so either the read is a blocking call a worker
   may make or the tick fetches the Chunks at dispatch, as it does for held
   children today. That choice belongs to the save step.
4. **An accepted Edit is readable the moment it is accepted**, not when a batch
   flushes. A coarse job must never see older Voxels than a level-0 reload
   would, or the two levels disagree about the same place.

When all four are answered, rewrite the sections below against the real
interface, set `Status: ready-for-agent`, and have the maintainer accept the
emitter and levels-2-and-above decisions before any code.

## Trigger

The first commit of a save step that persists level-0 Chunks. Not before:
without durability the in-memory overlay below is the only honest option, and it
is a stopgap, not this ticket.

## What changes

### One source of level-0 truth

A coarse Chunk reads level 0 through one rule: the held Chunk if the store has
it, else the saved Chunk, else the generator. Everything below is a consequence
of there being one rule, so a coarse level and a level-0 reload can never
disagree.

### Which Chunks pay for it

Keep, per coarse level, the set of covers that have at least one saved level-0
Chunk in their footprint. Building it is one pass over the save's coordinates at
world open (each coordinate marks its cover at every level), and one insert per
newly saved Chunk afterwards. A cover **not** in the set is generated exactly as
today: from the source generators alone, with no read and no extra work. So an
untouched world costs what step 6 measured, and the bench numbers in DESIGN.md
must not move. A cover in the set is derived from the bottom up: its eight
children are themselves derived if they are in the next level's set, taken from
the saved or held level-0 Chunk at level 1, and generated by the source
generator otherwise. The cost is proportional to the edited area and to the
level count, not to the footprint, which at level 5 is 32 by 32 by 32 level-0
Chunks.

### `LodStore` invalidation

- An Edit invalidates its cover at **every** level where that cover is held or
  has a generate job in flight, not level 1 only. Today `stream_lod` drains the
  changed coordinates and invalidates level 1; this becomes a loop over levels.
- Eviction of an edited level-0 Chunk **stops** marking its cover. The Edit no
  longer stops existing when the Chunk leaves, so the cover is right as it is.
  `MeshState`'s `edited_chunks` set exists for that mark alone and goes, unless
  the save step finds another use for it. `voxels_changed` stays the one hook an
  Edit passes through, for the reason ticket 05 of the LOD spec recorded: light
  writes must not rebuild a cover.
- A coarse Chunk first made after the save loads is correct without a mark,
  because it reads the save.
- **Levels 2 and above are invalidated lazily.** Generation has no hole, so an
  Edit's cover is held at every level, and invalidating all of them rebuilds
  five coarse Chunks and remeshes their neighbours for every Voxel dug, none of
  them visible: the shader draws no coarse level inside the finer level's reach,
  and an Edit is within `EDIT_REACH_M` of the Eye. The mark is made, but a
  stale cover at level 2 or above whose Cell still lies inside the finer
  level's cut is not dispatched; it is picked up when an anchor move or the Eye
  leaving the cut makes it visible. A test pins that a dig in place dispatches
  no job above level 1, and that walking away rebuilds exactly the covers that
  went stale.

### The downsample

The volume rule is unchanged: solid at half the volume, a full cube, the
dominant Material by volume with the existing tie-breaks. The only change is the
emitter rule below, which needs the Material table. `downsample` gains it as an
input, which is the first time `tesserae-core`'s LOD module reads one; it stays
free of Bevy and wgpu, so invariant 3 holds.

### The emitter rule

A coarse Voxel that passes the half-volume test and has at least one emissive
child takes the Material of the child with the greatest emission, not the
dominant Material. Ties between emitters fall back to the existing rule among
them. A Voxel that fails the test stays air, so a hanging lantern with nothing
around it still vanishes, as a pane does.

What the rule does and does not buy, because the ADR's "one line" understates
it:

- **It keeps the Material, not the glow.** Emission is read only by the light
  solver, and a coarse level is meshed with full sky light and no block light.
  A surviving lantern is a lantern-coloured cube lit like the ground around it.
  A glow needs a block-light term in the coarse mesher, which also breaks the
  single synthetic light that lets coarse faces merge maximally. That is a
  separate ticket and is not assumed here.
- **It inflates with the level.** A lantern on a hillside at level 3 is an
  8 m cube of lantern Material, and at level 5 a 32 m one, visible from 4 km.
  Whether that reads as a beacon or as a bug depends on the Material's colour
  and is not knowable from the code. Decide before building: apply the rule at
  every level, or only up to a stated level. The ticket's default is levels 1
  and 2, on the argument that a lantern is the size of a Voxel and a coarse cube
  beyond 4 m is no longer it.
- **Nothing generates an emitter today**, so the rule has no effect until a
  player or a Mod places one and the save keeps it. That is the reason it waits
  for this ticket and not for step 6.

## Alternative: an in-memory edit overlay, as a stopgap

If the save step is far off and Edits are being made, the loss can be fixed
sooner, without a save. When a level-0 Chunk that has been edited leaves the
store, keep it in an overlay keyed by coordinate instead of dropping it, and let
the coarse jobs read held-or-overlay. The ghost the eviction mark exists to
avoid goes away because the Edit never stops existing.

Why it is not the recommendation:

- **Unbounded memory.** Nothing ever releases an overlay entry for the life of
  the process. A Chunk is up to 128 KiB raw (32768 Voxels at four bytes) before
  palette compression, so a long session digging through ten thousand Chunks is
  on the order of a gigabyte. A cap means evicting an entry, which brings the
  ghost back.
- **It is only coherent if level 0 reads it too.** If the overlay feeds coarse
  jobs but a returning Eye regenerates the Chunk from the generator, the Edit is
  visible at level 1, absent at level 0, and visible again at level 1 in the
  next session. So the overlay must also supply level-0 reloads, which makes it
  a save that lives in memory: the thing being waited for, built twice.
- **It is thrown away at save time.** The save's sparse coordinate set and its
  read path replace the overlay behind the same one-rule seam, so the stopgap's
  only lasting value is the seam. That value is real, and is the reason to build
  the seam first if the stopgap is ever built: the coarse jobs ask "level-0
  truth for this coordinate" and know nothing about where it lives.

Build it only if the save step slips and a tester is losing visible work. Even
then, keep it behind the seam so deleting it is one removal.

## Do levels 2 and above ever need Edits?

Yes, once level 0 is durable, and the ADR's reasoning stops holding. It rests on
an Edit being metres from the Eye, where no coarse level is drawn. That is true
of a fresh Edit and false of a saved one: a base built at the spawn is 1 km away
the next session, drawn at level 3. Without Edits at levels 2 and above, a
player's own tower is replaced by the generator's hill beyond 256 m.

What does not follow is that every Edit shows up. A level-k Voxel is `2^k`
Voxels wide, so one placed Voxel changes it only if it flips the half-volume
test or the dominant Material, and a pane, a fence or a single lantern does
neither. At levels 4 and 5 only mass Edits (a quarry, a long wall, a crater)
register. That is the rule working, not a gap.

The ticket's default is **no cap**: the saved-cover set already makes the cost
proportional to what was edited, and a cap is a magic number that hides a
saved build from one level to the next. If the numbers say a level is not worth
its cost, the measurement below is where that shows.

One risk to measure and not assume away. Above level 1 the unedited neighbours
come from the coarse source generator and the edited footprint comes from
downsampling finer Voxels, and those two are not the same terrain. At a level-1
cover they are the same by construction, which is what the ADR relies on. At
level 2 and above the edited cover and its unedited neighbours may disagree by
a Voxel along the footprint's edge. Measure the step against the seam capture of
ticket 08 of the LOD spec; if it is visible, derive a one-Chunk border around
each edited footprint the same way.

## Out of scope

- A glow for coarse emitters.
- A coarse level storing or being edited itself. Coarse Chunks stay derived.
- Light at coarse levels. Full sky stays.
- The save format, its transport and its flush policy. This ticket consumes the
  four things in "What it is blocked on" and defines none of them.
- Level 0 streaming, apart from removing the eviction mark.

## Acceptance criteria

- [ ] Every level's Chunk that covers a saved level-0 Chunk equals the downsample
      chain of the saved Voxels, at levels 1 to 5, and a cover with no saved
      Chunk in its footprint is the Chunk step 6 made, bit for bit.
- [ ] Evicting an edited level-0 Chunk dispatches no coarse job and leaves its
      cover as it was; the Edit is still visible at level 1 afterwards.
- [ ] An Edit invalidates its cover at each level where it is held, and a dig in
      place dispatches no job above level 1 until the Eye leaves the cut.
- [ ] A lantern placed against solid ground survives to the stated level as the
      lantern Material; a lantern with nothing around it vanishes at level 1.
- [ ] The default-reach benchmark on an unedited world is within the noise of
      the step 6 numbers, and the cost of a world with a stated number of saved
      Chunks is reported per level.
- [ ] The step against an unedited neighbour at levels 2 and above is measured
      and either shown to be under a Voxel or removed.
- [ ] No new `pub` mutator outside `crate::server`; `tesserae-core` gains no
      dependency; ADR-0011 and the docs below are updated in the same commit.
- [ ] `./scripts/cargo-ci`, `cargo fmt --all --check` and `npm run fmt:check`
      pass.

## Tests

- **Core.** `downsample` with a Material table: an emitter among solid children
  wins over the dominant Material; the same emitter among mostly air children
  yields air; two emitters of different emission pick the stronger; a tie among
  emitters uses the existing rule; a table with no emitter gives the result of
  today's tests unchanged. Property-style: with a table whose every emission is
  zero, the new function equals the old for every case the old tests cover.
- **Store.** An Edit in a held Chunk with held covers at levels 1 to 3 marks all
  three; the same Edit with the level-2 cover absent marks two and builds the
  third later with the Edit in it.
- **Eviction.** Walk the Eye away until an edited Chunk is evicted: no job is
  dispatched, the level-1 cover is the same `Arc`, and the Edit is still in it.
  Walk back: level 0 reloads the Edit from the save and its mesh equals the one
  before.
- **Laziness.** Dig repeatedly in one place: no generate job above level 1.
  Walk 300 m: exactly the covers that went stale are rebuilt, each once.
- **One rule.** For every level, the coarse Chunk built from a held Chunk and the
  one built after that Chunk is evicted and reloaded are equal. A mutation that
  reads the generator for an evicted Chunk fails it.
- **Cold open.** Open a world with saved Chunks and no Eye movement: the covers
  of the saved Chunks contain the Edits on first generation, with no mark.
- **Cheap path.** A cover with nothing saved under it dispatches the same jobs as
  step 6; count generator calls over a full fill.
- **Starvation.** Sustained Edits still deliver meshes at every level, as ticket
  05 of the LOD spec tested for level 1.

## ADR-0011 and the other text to update

ADR-0011 stays accepted and its title stays true (coarse Chunks are still
derived, never stored and never edited). Amend it, do not supersede it. Change:

- **Context, last sentence.** "There is also no save yet, so nothing durable says
  what an Edit changed." Replace with the save step's fact: a save now says what
  an Edit changed, which is the input.
- **Decision, first paragraph.** "a pure function of the seed, the parameters and
  the level-0 Chunks the Server holds that an Edit changed". Replace with: a
  pure function of the seed, the parameters and the saved level-0 Chunks, where
  a held Chunk takes precedence over its saved copy.
- **Invalidation, the whole paragraph.** Replace it with: an Edit marks its cover
  stale at every level where it is held, lazily above level 1 while it lies
  inside the finer level's cut; a level-0 Chunk leaving the store marks nothing,
  because its Edits are saved; and the sentence "levels 2 and above read the
  generator alone and are never invalidated" is deleted along with the reason
  after it, which holds for a fresh Edit and not a saved one.
- **Consequences, first bullet.** "An Edit is visible at levels 0 and 1 only, and
  only while its level-0 Chunk is held." Delete; replace with the new loss: an
  Edit smaller than half a coarse Voxel is not visible at that level.
- **Consequences, second bullet.** Emitters now survive as a Material at the
  levels the rule covers and still carry no block light.
- **Consequences, fourth bullet.** "The save format is unchanged" stays, and
  gains the sparse coordinate set as the one thing the save step provides for
  this.
- **"Revisit when a save step makes level 0 durable".** Delete the section; it
  is this ticket. If the emitter rule is capped at a level, add the cap and its
  reason as a consequence.

Outside the ADR:

- `DESIGN.md`, the LOD section's downsample bullet gets the same exception and

- `.scratch/2026-10-13-phase-6-lod/spec.md`: its "Known loose ends" entries on
